# Runbook
1. Run the complete local suite and fixture as shown in README. Save the verification output and manifest; do not reuse the output directory.
2. For provider rehearsal, select an approved test origin and publication destination. Verify provider limits and exact raw response, implement runtime credentials through approved storage, prove freshness-source signature validation, and capture the provider-backed run in a new evidence directory.
3. Test one short remote scheduled rehearsal with no manual trigger. [Render Cron](https://render.com/docs/cronjobs) has a $1/month service minimum, so it is not provisioned. [GitHub Actions scheduling](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule) is a candidate subject to account limits, actual latency and possible dropped runs. Its default-branch behavior makes explicit revision checks mandatory. Keep manual and scheduled run IDs separate; fail closed outside a pre-registered window.
4. Confirm all EXPERIMENT gates with the operator before any official schedule or publication. Keep public evidence free of personal data and secrets. Preserve failures rather than rescuing the run.
