# Experiment and gates
- Local gate: autonomous fixture control flow in separate processes, scope limits, intentional tampering detected, hashes and raw rendezvous page retained. Fixture freshness is synthetic and same-host process separation is not OS isolation.
- Provider manual gate: disposable non-live ID; approved public root; publish a signed or independently timestamped beacon; no direct beacon input to fresh B; actual Firecrawl discovery and preserved provider response; independently verified external pulse; remote response published by B; independent verifier. Verify safe crawl behavior before using a real root.
- Short scheduled gate: same provider checks, disposable ID, fresh runner, exact external code revision, observable schedule origin, UTC start window, fail closed on wrong event/revision, no cached artifacts or manual trigger. Repeats must not overwrite evidence. A once-only externally enforced run or durable claim must be demonstrated before live.
- Live gate: first two rehearsals and scheduled gate pass, schema and code frozen, public-before-T1 provenance, autonomous attributable response, independent freshness and cryptographic linkage, uncontaminated startup/publishing evidence and final manifest. Any disqualifying manual intervention or missing evidence results in FAILED or INCOMPLETE. No reclassification to PASS based on local fixtures.
- Model gate: this fixture is deterministic. If the claim specifies AI agents, identify a bounded model decision in the actual run and record its exact inputs, output and role separately from deterministic verification.
