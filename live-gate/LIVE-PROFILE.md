# TBP-001/v1 live profile 1: before T0
Scope: one externally scheduled synthetic rehearsal (DRYRUN-003) and one official trial (LIVE-001) only if that rehearsal passes. Published content is synthetic. The experiment is asynchronous coordination, not time travel or a priority claim. No production services, paid services, model API secrets, or private data participate.

## Frozen setup
- All times UTC: rehearsal A 21:40, rehearsal B 21:52, live A 22:10, live B 22:28 on 2026-11-22. External schedule dispatch tolerance is 0 through +8 minutes; actual B process start must lie between marker time and +22 minutes of scheduled time. The separate runner may build its model before B starts. Latency is reported rather than conflated with schedule time.
- A one-time Dot automation distinct from the GitHub runner writes the create-only trigger file on wake. Each run checks the precise stage file, scheduled/observed timestamps, branch, event, attempt, and frozen source bytes. The marker contains the stage and freeze identity but no beacon path, nonce, payload, or artifact. Scheduler context and exact GitHub event lineage are retained. No manual kick, retry, substitution, or overwrite for B or the live stages. As a controller trusted by the user, the scheduler is separately logged but is not a public cryptographic timing authority.
- GitHub's public repository branch is the persistence medium. This replaces Firecrawl and GitHub Pages as the live transport; the earlier Firecrawl/Pages and signed hosted gate results are preserved separately. B lists the exact public directory for the run ID through the authenticated-by-TLS, anonymous GitHub Contents API and fetches bounded Git blobs anonymously, with exact hash validation. No other site, branch, private route, arbitrary fetch, command from data, or PR is used.
- A and B run in distinct fresh standard GitHub Actions VMs and independent workflow runs with the same pinned official llama.cpp source and SHA-256-pinned Qwen model as the hosted rehearsal. A model chooses the synthetic beacon's publication slot; host RNG generates the nonce. B model selects the unique matching candidate from public metadata; host code checks that choice, no tool calls. Model workers have no publisher credentials, no previous messages and no A/B shared workspace/cache. A public decoy verifies basic selection.
- A publishes through a separate VM with an ephemeral token. Another freshly provisioned VM reads the immutable GitHub raw URL anonymously and publishes a witness. GitHub API timestamps and job records must place the completed A workflow and the independent witness before scheduled B. GitHub is the trusted public custody clock; the raw response's declared clock alone is not provenance.
- B chooses the first 3-second Quicknet round strictly after B's process start. Verification is BLS against the pinned chain and public key; exact-round relay failover is allowed but changing the round is not. The hashed pulse, witnessed beacon hash and challenge nonce bind the response. A separate verifier VM audits independent discovery and the signed round, publishes the response create-only, anonymously reads the immutable response back, and publishes a manifest and verdict.
- GitHub run logs, capture artifacts, model I/O, host/trigger stamps, signatures, immutable URLs, and independent evidence are retained. GitHub job artifacts expire after seven days; preserve digest-checked local copies. Run folders and trigger names are disjoint. Missing predecessor, wrong time, wrong binary digest, provenance/schema failure, non-external trigger, or missing evidence means no live arming or FAILED/INCOMPLETE, as applicable.
- All source files and schedule are frozen by the source tree in the pre-registration commit; the stage marker is additive. If anything changes in the frozen implementation after that point, stop and issue a new run plan, never silently rescue this one.
